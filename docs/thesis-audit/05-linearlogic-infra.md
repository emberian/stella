## (a) The linear-logic / proof-net / cut-elimination correspondence

### What Eng formalizes

Eng's transcendental syntax is a *deliberate* re-grounding of proof theory on
computation: stellar resolution (logic-free first-order clausal resolution with
tile-system dynamics) is the substrate, and *linear logic is recovered from it*,
not assumed. The MLL story has three layered claims, all of which the in-repo
digests carry at spec grade:

1. **GoI / cut-elimination as path computation** (TLL §4.1; Eng Ch 10 §66–67).
   A proof-structure's axioms induce a permutation on atoms (loci); cuts are a
   partial permutation; cut-elimination is the computation of maximal
   alternating paths between the axiom graph and the cut graph — i.e. edge
   contraction. Stellar resolution generalizes this: binary stars encode graph
   edges, and `Ex(Φ)` *is* the set of maximal paths. The worked TLL example
   `Φ = [+c(1),-c(3)]+[+c(4),5]+[+c(2),6]+[7,8] ⊎ [-c(1),-c(2)]+[-c(3),-c(4)]`
   normalizing to `[5,6]+[7,8]` is the canonical "cut-elim = resolution" demo.
   Eng's full version (Ch 10 §66.11) uses path-address terms `t ::= X | 1·t |
   r·t` so that ⊗/⅋ cuts (not just atomic cuts) are simulated — the cut star
   *duplicates during execution*, encoding the proof-structure shape directly
   into addresses. **Headline metatheorem: §67.10** (simulation of proof-net
   reduction: `AEx(Φ_R^comp) ≃_S Φ_S^ax` for `R ↝* S`, S cut-free).

2. **Danos-Regnier correctness as testing** (TLL §4.2, §5.2; Eng Ch 10 §68).
   Logical correctness = the proof-structure constellation, executed against
   *every* switching-graph constellation, produces the conclusion star. This is
   the philosophically load-bearing move: correctness becomes *unit testing /
   model checking* (orthogonality `Φ ⊥ Φ′`), not a semantic side-condition.
   `Φ ⊥ Φ′` when `|Ex(Φ⊎Φ′)| < ∞` captures **MLL+MIX**; `|Ex|=1` is the
   (insufficient) MLL attempt. **Metatheorem: §68.19.**

3. **Behaviours / interactive typing** (TLL §5.3–6, Eng frontier). Types =
   bi-orthogonally-closed sets of constellations; a formula's tests are
   *generated by the formula*, independent of any proof. This is the exact
   structural template the stella thesis reuses for **§2.2 reafferent closure
   = Girard bi-orthogonality in a sensorimotor coat** (`docs/00` §2.2). The
   atom-as-individual / "two constellations with the same topology are the same
   type" idea (TLL §6.2) is the seed of the §80 ω-weight / structural-identity
   work already in `omega_weight.rs`.

### What we already exploit (substantial — this is a strength, not a gap)

The MLL layer is **the most thesis-faithful, best-tested part of the codebase**:

- `mll.rs` (3.5k LOC, **23 tests**): `ProofStructure`, path addresses
  (`path_addr`, §66.7), `phi_ax`/`phi_cut`/`phi_comp` (§66.11), cut-elimination
  via `cut_elim_via_aex` (Thm 67.10, hand-computed test
  `test_theorem_67_10_hand_computed`), and **full §68 Danos-Regnier** —
  `all_switchings` (2^k), `phi_switched_coloured`, `dr_correct` (stellar
  §68.19) cross-checked against `dr_correct_classical` (the classical
  switching-graph acyclic+connected oracle, §68.21). This is a genuine
  *differential-oracle pair* and it is the cleanest one in the repo.
- `mll2i.rs` (95k, **13 tests**): MLL2I / intuitionistic implication (Ch 11
  §73–76), the §74.7 black-hole weakening star `[+addr(v),+ω(X),−ω(f(X))]`,
  Girard's original correctness criterion `girard_correct`. The §74.7
  black-hole is *the* substrate primitive the thesis uses for positive death
  certification (`docs/00` §5.x RESOLVED note) — it is directly load-bearing
  for the valence work, not a logic curiosity.
- `ch9.rs` (**9 tests**): the §62 structural classifier (tame vs.
  non-termination-risk via `D[Φ;C]` ray classification — free/deterministic/
  branching). This is the bridge object: it is *defined in the MLL/automata
  vocabulary* but is the gate `reafference.rs` uses to decide closure
  candidacy. The objective-idempotence / subjective-non-idempotence dividing
  line (§49.55 / §49.57) is the formal definition of "dead vs. alive" the whole
  valence thesis rests on (`docs/00` §4.4).

So the proof-net correspondence is **not** an infrastructure gap at the
*encoding* level. The gap is that the MLL machinery is used as a *static
correctness checker*, never as a **dynamical / trajectory** object — see §(c).

### What Eng formalizes that we do NOT exploit

- **§67 ⊗/⅋ non-atomic cut duplication via open-hypergraph SMC rewriting.**
  `mll.rs:44-54` is an explicit, honest TODO: cut-elimination is run through the
  ordinary `aex_*` engine, not as a string-diagram rewrite, because
  `open-hypergraphs` 0.3.x lacks `matches`/`rewrite` combinators. Eng's
  per-step cut-reduction-as-rewrite is the natural home for the Ch 10 layer and
  is the one place `open-hypergraphs` is genuinely the right model (`docs/00`
  §5). Currently unexploited.
- **§68–72 behaviours / units / the full type structure.** `mll.rs` stops at
  DR correctness; behaviours (bi-orthogonal closure as a *computed* object,
  TLL §5.3–6) are only present implicitly via `reafference::solve_for_closure`,
  never as a reusable `Behaviour` type. The thesis's strongest structural claim
  (reafferent closure = bi-orthogonality) has **no shared datatype** with the
  MLL bi-orthogonality that is already implemented — they are two unconnected
  implementations of the same Eng construction. This is the single highest-value
  *conceptual* consolidation available (see gap #2).
- **MLL+MIX vs MLL orthogonality distinction** (`|Ex|<∞` vs `|Ex|=1`,
  TLL §5.3). `dr_correct` uses the strong-normalization side; the cardinality
  refinement that separates MLL from MLL+MIX is not surfaced as a knob.

## (b) The autodidactic / learning framing — honest assessment

**Verdict: mostly out of scope as physics; one structural import is real and
already (independently) in the codebase; one is a genuine, currently-absent
methodological frame worth one experiment.**

The Autodidactic Universe paper is a *physics* program: gauge/gravity theories
put in correspondence with RBM/matrix-model learning dynamics
(Plebanski/Chern-Simons ↔ restricted Boltzmann machine forward/backward pass +
matrix-square-root update). The matrix-model / RG-learning / geometrogenesis
machinery has **no encodable contact** with stellar resolution and should be
declared out of scope. Pretending otherwise would be exactly the kind of
over-framing `~/.claude` memory `feedback_no_valence_overframing` warns against.

What *is* relevant, stated conservatively:

1. **AU §1.1's "system / process / Kantian whole / closed process that returns
   to its initial state" definition of a learning system is structurally
   isomorphic to the stella §2.2 reafferent closure** — and was reached
   independently. AU: "a system learns when it can alter its internal processes
   to better exploit flows through it to further continued existence"; stella:
   the agent is the sub-constellation whose reafference cycle closes, with
   viability-under-perturbation as the gradient. This is a *fourth independent
   arrival* at the closure/Kantian-whole structure (cf. `docs/00` §3 "four
   convergences"). It is **already encoded** (`reafference.rs`, `valence.rs`) —
   so the AU framing is *corroborating*, not *actionable*: it adds external
   evidence the architecture is found-not-assembled, nothing to build.

2. **AU §5.2 "consequencer" (a sub-process that accumulates past information
   that is more influential on the future than typical) is a clean operational
   target the substrate can express and currently does NOT measure.** A
   subjective ray that, once created during §49.50 dynamics, biases all
   subsequent matchable frontiers is *literally a consequencer*. The repo has
   `accel_detect::detect_recurrence` (a trace recurrence/generalizer) but no
   "consequencer-density" / information-influence metric on a trace. This is the
   single encodable, in-scope idea from AU — see experiment #2.

3. **AU §1.1's autodidactic distinction (system constructs its *own* criteria,
   vs. engineered/imposed criteria) is exactly the stella pre-registered
   null** (`docs/00` §6: "attraction/repulsion only accretes under per-task
   hand-tuning ⇒ project fails"). AU gives this distinction independent
   philosophical articulation and an irreversibility angle (§5.3.1–2: can
   irreversible learning arise from reversible laws? — directly parallel to
   Eng's idempotent-objective vs. non-idempotent-subjective split, §49.55/57).
   This is **framing reinforcement, not new infrastructure**.

Recommendation: cite AU once, in `docs/00` §3, as the external/fourth
convergence and as independent grounding for the autodidactic null; do **not**
import matrix-model/RG learning machinery. The "consequencer" metric is the only
buildable item and it is small.

## (c) THE KEY DELIVERABLE — consolidated supporting-infrastructure gaps

Prioritized. Each gap is concrete (what artifact, where it plugs in, why
thesis-grounded). "Already have" cross-refs are in §(d).

### P1 — Cut-elimination *trajectory* tap (the MLL layer has no time axis)

`cut_elim_via_aex` returns a final-state `CutElimResult`; `dr_correct` returns a
`bool`. Neither emits the **reduction sequence**. The thesis's entire charge
mechanism is `[t_birth, t_death)` trajectories and non-idempotence *over steps*
(`docs/00` §2.4, §4.4). MLL cut-elimination is Eng's *cleanest, provably
confluent/terminating* (§67) dynamical system and we throw the trajectory away.
**Need:** a `cut_elim_trace(ps) -> Vec<ReductionStep>` (each step: the diagram
contracted, the substitution, the surviving star multiset) reusing the same
`Step` shape `subjective.rs`/`valence.rs` already consume. This makes the
proof-net layer a *dynamical testbed with a ground-truth normal form* — the
ideal differential-oracle target because §67.10 *guarantees* the answer.

### P2 — A shared `Behaviour` (bi-orthogonal closure) type unifying MLL typing and §2.2 reafferent closure

The thesis's load-bearing claim is "reafferent closure = Girard
bi-orthogonality" (`docs/00` §2.2, §3 convergence #3). MLL bi-orthogonality is
*implemented* (`dr_correct` orthogonality, TLL §5.3 `Φ⊥Φ′`); reafferent closure
is *separately* implemented (`reafference::solve_for_closure`). They share no
datatype. **Need:** one `Behaviour { tests, members, ortho }` abstraction with
the orthogonality relation parameterized (`|Ex|<∞` for MLL+MIX; the §2.2
provenance-cycle predicate for closures). This is the consolidation that turns
the "four convergences" claim from prose into a single reused code object — the
strongest honesty upgrade available, and it directly de-risks the §6 null
("§2.3 is decoration not structure").

### P3 — `open-hypergraphs` SMC cut-rewrite layer (or a documented decision to drop it)

`mll.rs:44-54` and `docs/00` §5 both flag this. Either wire §67 cut-reduction
as an open-hypergraph rewrite (the one place the dependency is the right model),
or record a dated decision that 0.3.x cannot express polarised α-unification as
an SMC rewrite and the dependency stays viz-only. Right now it is an open TODO
that costs a workspace dependency and a recurring "why is this here" question
(`docs/07` notes the dep is otherwise viz-only). Lower than P1/P2 because it is
engineering-elegance, not thesis-blocking — but it should be *resolved*, not
left ambient.

### P4 — A proof-net / switching-graph **visualizer** (trace-aware, not just static)

`viz.rs` emits DOT for `D[Φ;C]` and a single `Diagram`. There is **no**
visualizer for: a `ProofStructure`, its 2^k switchings side-by-side, or a
*cut-elimination animation*. The user's memory (`feedback_ux_richinputs`)
explicitly wants diagrams over raw JSON, and `docs/00` §4.5 names
"open-hypergraphs-dot visualization" as a milestone deliverable. Pairs with P1:
once a trajectory tap exists, a per-step DOT/SVG dump of the contracting
proof-net is the highest-leverage explanatory artifact in the project.

### P5 — A unified differential-oracle harness spanning the MLL ↔ subjective stack

Differential oracles exist but are *siloed*: `faithfulness.rs` (unifier
result-compat), `mll.rs` (`dr_correct` vs `dr_correct_classical`),
`execution.rs` (`aex_full`/`aex_seminaive`/`aex_stratified` α-equivalence),
`docs/07` (`iex` vs `iex_fast`, KS/KA differential gates). There is no single
harness that, given a constellation, runs *all applicable* oracles and reports a
consolidated compatibility verdict. The thesis depends on "reference engine =
spec, accelerated = checked" everywhere; the absence of one entry point means
each new fast path re-implements the gate. **Need:** `oracle::check_all(Φ) ->
OracleReport` aggregating the existing pairwise oracles. This is pure
consolidation of code that already exists — cheapest high-value item.

#### Lower-tier / noted, not top-5

- No **MLL/MLL2I corpus file** (proof-structures as data); every test
  hand-builds `ProofStructure`s inline. A small `corpus/mll/*.ps` + loader would
  let the differential oracle sweep proof-nets the way `experiment.rs` sweeps
  the subjective corpus.
- No **MLL+MIX vs MLL knob** on `dr_correct` (the `|Ex|<∞` vs `|Ex|=1`
  distinction, TLL §5.3) — currently only the strong-normalization side.
- No **consequencer / information-influence metric** on traces (the one AU
  import; see experiment #2).
- §68–72 **behaviours/units** beyond DR correctness are unimplemented (subsumed
  by P2 if P2 is built generically).
